# Personal Finance Manager

Консольное Java-приложение для учёта личных финансов. Учебный проект по ООП для Promo IT.

**Требования:** JDK 17 или новее, Maven 3.8+, IntelliJ IDEA (необязательно). **Без Spring Boot и базы данных.**

## Возможности

- Регистрация и вход по логину/паролю, отдельные кошельки нескольких пользователей.
- Учёт доходов/расходов с точной денежной арифметикой (`BigDecimal`).
- Создание, переименование, удаление пустых категорий доходов и расходов.
- Установка и изменение бюджетов по категориям расходов, вывод потраченного и остатка.
- Сводные суммы, баланс, разбивка по категориям и выборка по нескольким категориям.
- Оповещения при достижении 80% бюджета, превышении бюджета, отрицательном или нулевом балансе.
- Переводы по логину получателя: расход у отправителя + доход у получателя.
- Сохранение состояния при `logout`, `exit` и завершении ввода (EOF); восстановление из JSON при запуске.
- Экспорт/импорт **JSON-снимка кошелька** текущего пользователя.
- Цикл команд с `help`, понятными сообщениями об ошибках и кавычками для названий с пробелами.

## Запуск в IntelliJ IDEA

1. Распаковать архив и открыть **папку с `pom.xml`** как Maven-проект.
2. Выбрать JDK 17 или новее (в настройках Project SDK и Maven Runner).
3. Запустить `ru.homework.finance.FinanceApplication.main()` кнопкой **Run ▶**.
4. В Run Configuration параметр **Working directory** должен быть корнем проекта (где находится `config/application.properties`).
5. В консоли ввести `help`.

Запуск через терминал из корня проекта:

```bash
mvn clean verify
java -jar target/personal-finance-manager.jar
```

Можно передать путь к другому properties-файлу:

```bash
java -jar target/personal-finance-manager.jar config/application.properties
```

Значения по умолчанию задаются в `config/application.properties`:

```properties
app.data-file=data/finance-state.json
app.exports-directory=data/exports
```

Эти пути относительны рабочей директории приложения. Файлы создаются автоматически, если их ещё нет. Папка `data/` добавлена в `.gitignore`.

## Первое использование

Вводи команды **по одной строке** в консоли (командную строку после приглашения `finance>`). Пример:

```text
register alice
# Приложение попросит придумать пароль и повторить его; минимум 8 символов.
category add income "Зарплата"
category add income "Бонус"
category add expense "Еда"
category add expense "Коммунальные услуги"
budget set "Еда" 4000
budget set "Коммунальные услуги" 2500
income "Зарплата" 20000
income "Бонус" 3000
expense "Еда" 300
expense "Коммунальные услуги" 3000
report
report "Еда" "Коммунальные услуги"
history
exit
```

**Важно:** строки с `#` в примере — пояснения README, **не** команды. Пароль вводится на отдельных приглашениях программы. В IntelliJ IDEA ввод пароля может быть виден в окне Run (`System.console()` обычно недоступен); не используйте реальные пароли. В стандартном терминале Java скрывает ввод через `Console.readPassword()`.

## Список команд

| Команда | Описание |
| --- | --- |
| `register alice` | Зарегистрировать пользователя и войти (пароль вводится отдельно) |
| `login alice` | Войти после перезапуска по паролю |
| `logout` | Сохранить состояние и выйти из аккаунта |
| `whoami` | Показать текущий логин |
| `category add income "Зарплата"` | Создать категорию доходов |
| `category add expense "Еда"` | Создать категорию расходов |
| `category rename expense "Еда" "Продукты"` | Переименовать категорию с переносом операций и бюджета |
| `category delete expense "Еда"` | Удалить пустую категорию без бюджета |
| `budget set "Еда" 4000` | Создать/изменить бюджет категории расходов |
| `budget remove "Еда"` | Удалить бюджет категории |
| `income "Зарплата" 20000` | Добавить доход |
| `expense "Еда" 300.50` | Добавить расход |
| `report` | Общая сводка по всем категориям |
| `report "Еда" "Такси"` | Сводка по нескольким выбранным категориям |
| `history` | История операций текущего пользователя |
| `transfer bobby 500` | Перевести 500 пользователю `bobby` (он должен быть зарегистрирован) |
| `export backup` | Записать `data/exports/backup.json` (снимок текущего кошелька) |
| `import backup` | Заменить текущий кошелёк данными из `backup.json` |
| `help` | Показать команды с примерами |
| `exit` / `quit` | Сохранить все кошельки и завершить программу |

Названия категорий с пробелами заключаются в двойные кавычки. Операции можно проводить только для зарегистрированных категорий. В сумму можно писать `300.50` или `300,50`. Разрешено до двух десятичных знаков.

## Логика бюджетов и баланса

- **Общий доход** = сумма всех операций `INCOME`.
- **Общий расход** = сумма всех операций `EXPENSE`.
- **Баланс** = общий доход − общий расход.
- **Остаток бюджета** = установленный бюджет − расходы категории (может быть отрицательным).
- Бюджет **не блокирует** новый расход: он вызывает предупреждение, поскольку ТЗ требует оповещения при превышении.
- Отчёт с выбранными категориями показывает только их доходы/расходы; строка **«Текущий баланс (все операции)»** всегда показывает полный баланс.
- Категории для доходов и расходов разделены даже если называются одинаково.
- Перевод допускается только при достаточном положительном остатке отправителя. Для переводов автоматически создаётся категория `Переводы` у обеих сторон.
- При удалении категории с операциями система предложит переименование, чтобы не потерять историю.

## Проверка на числах из ТЗ

Зарегистрируй пользователя, создай категории и введи:

**Расходы:** `Еда` 300 и 500; `Развлечения` 3000; `Коммунальные услуги` 3000; `Такси` 1500.

**Доходы:** `Зарплата` 20000 и 40000; `Бонус` 3000.

**Бюджеты:** `Еда` 4000; `Развлечения` 3000; `Коммунальные услуги` 2500.

Команда `report` покажет:

```text
Доходы по выборке:  63000.00
  Зарплата                         60000.00
  Бонус                             3000.00
Расходы по выборке: 8300.00
Текущий баланс (все операции): 54700.00
...
Еда                         4000.00         800.00        3200.00
Развлечения                  3000.00        3000.00           0.00
Коммунальные услуги          2500.00        3000.00        -500.00
```

Порядок строк может отличаться. Отрицательный остаток по коммунальным услугам означает превышение бюджета на 500.

## Проверка нескольких пользователей и переводов

```text
register alice
# ввести пароль дважды
category add income "Зарплата"
income "Зарплата" 1000
logout
register bobby
# ввести пароль дважды
logout
login alice
# ввести пароль
transfer bobby 200
report
logout
login bobby
# ввести пароль
report
history
exit
```

Ожидается баланс `800.00` у `alice`, `200.00` у `bobby`. У получателя запись дохода и контрагент `alice`.

## Перезапуск, экспорт и импорт

После `exit` запусти программу снова, выполни `login alice` и введи тот же пароль: категории, бюджеты, операции и остатки будут восстановлены из `data/finance-state.json`.

Команда `export backup` пишет **только кошелёк** (категории, бюджеты и транзакции) в отдельный JSON, **не** пароли и других пользователей. Команда `import backup` **заменяет**, а не дополняет, кошелёк вошедшего пользователя. Импортируйте только свои доверенные локальные снимки; это демонстрационный механизм восстановления и он не рассчитан на аудит банковских переводов между разными импортированными снимками.

## Архитектура

```text
FinanceApplication
   ├── FinanceConsole              CLI, команды, пароль, вывод
   ├── FinanceService              бизнес-правила, пользователи, транзакции, переводы
   │      ├── UserRepository       интерфейс хранилища в памяти
   │      │     └── InMemoryUserRepository
   │      ├── PasswordService      PBKDF2 + случайная соль
   │      └── WalletValidator      проверка кошелька и операций
   └── SnapshotStore              интерфейс сохранения/импорта
          └── JsonSnapshotStore    JSON, временный файл + атомарная замена

model/: UserAccount, Wallet, FinanceTransaction, FinanceReport, Money, TransactionType
```

Приложение однопроцессное и консольное; `FinanceService` синхронизирует операции с двумя кошельками в рамках одного процесса, чтобы перевод обновлял обоих пользователей согласованно. Данные между командами находятся **в памяти**, JSON нужен только для перезапуска и импорта/экспорта. Отдельная база данных и REST API сознательно не добавлены — их нет в ТЗ.

Пароли защищены PBKDF2-HMAC-SHA256 с индивидуальной солью и не сохраняются в открытом виде. Доступ к операциям предоставляется через сессию в CLI после входа. При этом приложение является учебным локальным решением: файл данных не зашифрован, пользователей и переводы не следует считать финансовым сервисом промышленного уровня.

## Тестирование

Запустить полную сборку, JUnit 5 и Checkstyle:

```bash
mvn clean verify
```

В проекте больше 15 тестов, включая:

- регистрацию, неверный пароль, повторные имена, изоляцию пользователей;
- денежные расчёты, отсутствие категорий, недопустимые суммы;
- бюджеты, предупреждения о 80%, превышение бюджета и отрицательный баланс;
- выборку по нескольким категориям, переименование и удаление;
- успешные и неуспешные переводы;
- JSON-сохранение и восстановление после запуска, экспорт и импорт;
- реальный консольный сценарий (`register → операции → report → exit → login`).

**CI**: `.github/workflows/ci.yml` запускает `mvn -B clean verify` на JDK 17 при `push` и `pull_request`. Checkstyle применяет правила `checkstyle.xml`; `.editorconfig` задаёт базовое оформление файлов.

После загрузки на GitHub проверяй зелёный статус GitHub Actions. Не загружай `data/` и не публикуй реальные пароли.
